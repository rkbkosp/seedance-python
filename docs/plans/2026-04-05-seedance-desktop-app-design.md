# Seedance Desktop App Design

## 目标

当前项目只有一个命令行脚本，长提示词编辑、历史回看和素材复用都依赖终端，操作门槛偏高。本次改造目标是保留现有 Seedance API 能力，在本地提供一个跨 macOS 和 Windows 的轻量桌面应用，重点解决以下问题：

- 长提示词需要反复删改，要求编辑体验接近文档编辑器
- 生成记录要长期保存，并能回看视频、提示词、首尾帧和参考图
- 历史记录中的素材要能快速复用到新的任务中
- 生成好的视频要能直接拖到 Finder、桌面、Windows 资源管理器和其他应用
- 正在生成的任务要有清晰的加载动画和状态反馈
- 整体应用需要保持低内存占用和稳定的滚动、预览性能

## 技术选型

推荐技术栈如下：

- 桌面壳：Tauri 2
- 前端：SvelteKit
- 本地数据库：SQLite
- 元数据访问：Rust `sqlx` 或 `rusqlite`
- 本地文件管理：Rust 侧统一管理 `artifacts/`
- 缩略图生成：优先使用本地 `ffmpeg`，若不可用则退化为封面静态帧

选择理由：

- Tauri 相比 Electron 的常驻内存更低，更适合单用户本地媒体工具
- Svelte 的运行时开销比常见虚拟 DOM 方案更小，列表滚动和状态更新更轻
- SQLite 足够承载单机历史记录，并且适合分页、筛选、全文搜索和后续扩展
- Rust 侧天然适合处理本地文件、系统拖拽、后台任务轮询和跨平台路径管理

## 总体架构

应用拆成四层：

1. Seedance 服务层
   复用现有 Python CLI 的请求逻辑，但逐步把核心 API 封装迁移到 Rust 服务层，避免桌面端依赖外部 Python 运行时。

2. 任务调度层
   管理创建任务、轮询状态、下载视频、生成缩略图、更新数据库。前端不直接轮询远端 API，只订阅本地状态变更。

3. 数据存储层
   SQLite 负责元数据，`artifacts/` 目录负责视频、首尾帧、参考图和缩略图文件。

4. 前端展示层
   Svelte 页面负责表单编辑、历史列表、详情抽屉、拖拽复用和加载动画，不承担重 I/O 或复杂计算。

## 数据模型

第一版使用两张主表和一张可选扩展表。

### generations

保存一次生成任务的完整元数据。

关键字段建议：

- `id`：本地自增主键
- `task_id`：远端 Seedance 任务 ID
- `platform`：`volc` 或 `byteplus`
- `model`：模型标识
- `status`：`queued`、`running`、`succeeded`、`failed`、`cancelled`、`expired`
- `prompt`：完整提示词
- `prompt_summary`：用于列表展示的摘要
- `params_json`：时长、比例、分辨率等参数快照
- `video_path`：本地视频路径
- `thumbnail_path`：缩略图路径
- `first_frame_path`：本地首帧路径
- `last_frame_path`：本地尾帧路径
- `video_duration_ms`
- `video_width`
- `video_height`
- `created_at`
- `updated_at`
- `completed_at`
- `error_message`

### reference_images

保存一条生成记录关联的参考图列表。

关键字段建议：

- `id`
- `generation_id`
- `image_path`
- `source_kind`：`uploaded`、`reused`
- `sort_order`

### prompt_templates（第二阶段）

用于保存常用提示词模板，不阻塞第一版上线。

## 文件存储策略

所有媒体文件都必须先落盘，再进入 UI 展示和外部拖拽。推荐目录规则：

- 视频：`artifacts/videos/YYYY/MM/<generation_id>-<task_id>.mp4`
- 缩略图：`artifacts/thumbnails/YYYY/MM/<generation_id>.jpg`
- 首尾帧和参考图：`artifacts/images/YYYY/MM/...`

规则：

- 数据库只保存相对路径，应用启动时统一解析为绝对路径
- 删除记录时提供两种模式：仅删数据库、同时删数据库和文件
- 外部拖拽只允许对已存在的本地文件生效，不对远端 URL 做临时拖拽

## 主要页面

### 1. 生成页

生成页是主工作区，包含以下区域：

- 顶部大提示词输入框
- 首帧、尾帧、参考图上传区域
- 常用参数区：比例、分辨率、时长、固定镜头、水印等
- 当前任务状态区：队列中、生成中、成功、失败
- 提交按钮和取消按钮

行为约束：

- 提示词输入框支持较长文本，默认自动保存草稿
- 支持把历史记录中的提示词文本拖到输入框覆盖或插入
- 支持把历史记录中的首尾帧或参考图拖到对应上传区域复用
- 正在生成时保留当前输入，不强制清空

### 2. 历史页

历史页默认按时间倒序展示，每页固定 10 条记录。

每条卡片只渲染：

- 缩略图
- 状态标签
- 时间
- prompt 摘要
- 参考图数量
- 操作按钮：复用、详情、定位文件

默认不渲染视频元素。只有 hover 到卡片缩略图时，才临时加载该条视频并开始静音预览。

### 3. 详情抽屉

点击历史卡片后，从右侧打开详情抽屉，内容包括：

- 完整 prompt
- 全部参数
- 完整视频播放器
- 首帧、尾帧、参考图
- 原始任务 ID
- 文件路径和“在系统中显示”操作

详情抽屉承担“重内容查看”，列表页保持轻量。

## 拖拽设计

拖拽分为应用内复用和应用外导出两类。

### 应用内复用

- 拖拽 prompt 文本到发送框：默认覆盖整个提示词，也可按住修饰键选择插入模式
- 拖拽首帧或尾帧到对应槽位：替换原图片
- 拖拽参考图到参考图区域：追加到当前列表

### 应用外导出

历史卡片中的视频素材支持直接拖拽到：

- Finder
- macOS 桌面
- Windows 文件资源管理器
- 支持文件拖放的第三方 App

实现要求：

- 只能拖拽真实存在的本地视频文件
- 前端拖拽手势由 Tauri 原生能力接管
- 拖出时显示文件名和合法路径，不生成临时 Blob URL

## 任务状态与动画

正在生成的任务不放在历史列表内部频繁闪动，而是放在生成页顶部的“进行中任务条”中。

展示内容：

- 动态加载动画
- 状态文本
- 已耗时
- 如果后端能拿到进度，则显示百分比

后端统一轮询任务状态并通过事件推送给前端。前端只订阅一份任务流，避免每张卡片各自创建轮询器。

## 性能约束

这是第一版必须遵守的约束。

### 列表性能

- 历史页每次最多查询 10 条
- 翻页前不预加载后续视频文件
- 列表项默认只显示缩略图和少量文本
- 同一时间只允许一个 hover 预览视频播放

### 媒体加载

- 缩略图生成后长期缓存
- hover 进入 150ms 后再开始加载视频，避免划过时频繁触发
- hover 离开立刻暂停并释放视频资源
- 详情抽屉关闭时销毁播放器实例

### 内存控制

- 列表页避免同时挂多个 `<video>` 元素
- 图片区域使用受控尺寸和懒加载
- 不在前端保留整库历史缓存，只保留当前页和必要索引
- 数据查询分页走 SQLite，不扫描整个 `artifacts/`

## 后台任务流

一次生成任务的标准流程如下：

1. 前端提交表单
2. Rust 服务层写入一条 `queued` 记录
3. 调用 Seedance 创建远端任务
4. 更新 `task_id` 和状态为 `running`
5. 后台轮询远端状态
6. 成功后下载视频和最后一帧到本地
7. 生成缩略图并抽取媒体元数据
8. 更新数据库为 `succeeded`
9. 前端收到事件后刷新当前页和进行中任务条

失败时也要保留记录，用于后续排查和重试。

## 搜索与筛选

第一版建议支持以下轻量筛选：

- 全部
- 仅成功
- 仅失败
- 仅进行中

搜索功能可先实现为普通 `LIKE` 查询。若记录量明显上升，再加 SQLite FTS5 做 prompt 全文搜索。

## 实现阶段建议

### Phase 1

- 建立 Tauri + Svelte 基础工程
- 接入 SQLite
- 完成生成页基础表单
- 接入任务创建、轮询、下载
- 完成历史记录写入和分页列表

### Phase 2

- 加入缩略图生成
- 加入 hover 预览
- 加入详情抽屉
- 加入应用内拖拽复用

### Phase 3

- 加入系统级文件拖出
- 加入模板管理
- 加入搜索和筛选
- 加入删除和清理策略

## 风险点

- 系统级拖出在 macOS 和 Windows 的实现细节不同，需要单独验证
- 若本机没有 `ffmpeg`，缩略图生成策略需要有降级方案
- 若 Seedance API 返回的进度字段不稳定，前端动画应允许只显示状态和耗时
- 媒体文件命名和清理策略必须在第一版定清楚，否则后期迁移成本高

## 建议结论

基于当前需求，最合适的方向是：

- 保留现有 CLI 作为底层调试工具
- 新增 `Tauri + Svelte + SQLite` 桌面端
- 所有视频和图片先落本地，再做历史展示和外部拖拽
- 第一版优先把“生成、保存、分页历史、详情查看、低开销预览”做稳
- 第二版再补“系统级拖出、模板管理、全文搜索”
